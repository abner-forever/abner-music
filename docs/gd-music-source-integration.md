# GD 音乐台音乐源接入评估

核实日期：2026-10-27（Asia/Shanghai）。本文记录接口评估和接入方案；运行时已按本文实现，实施状态见文末。

## 结论

技术上可以接入。建议通过公开 API 增加「GD 音乐台」音乐源，提供在线搜索、播放、加入音乐库、收藏、歌单和歌词。现有播放器、网络音频通道和持久化可以复用。

应使用「平台 + 曲目 ID」标识歌曲，在播放时获取音频地址。网站首页不是音频直链，不能直接填入现有「添加网络音乐」表单。

## 官方入口与实测

- 用户提供的网站：`https://music.gdstudio.org/`
- 公开 API 与说明：`https://music-api.gdstudio.xyz/api.php`
- 本次读取的 API 说明更新日期为 2026-09-16。

| 能力          | 公开参数                                                   | 本次结果                                                                   |
| ------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| 搜索          | `types=search&source=netease&name=关键词&count=20&pages=1` | 网易云和 JOOX 搜索均返回曲目信息；样本中 JOOX 未遵循 `count=1`，返回 30 条 |
| 获取播放地址  | `types=url&source=netease&id=曲目ID&br=320`                | 网易云样本返回有效 HTTPS 地址与 `br=320`                                   |
| 音频可访问性  | 对返回地址发起 HEAD                                        | 网易云样本 HTTP 200、`audio/mpeg`、支持 `Accept-Ranges: bytes`             |
| 封面          | `types=pic&source=netease&id=pic_id&size=300`              | 返回 HTTPS 图片地址                                                        |
| 歌词          | `types=lyric&source=netease&id=lyric_id`                   | 返回带时间戳的 LRC；样本无翻译歌词                                         |
| JOOX 解析     | `types=url&source=joox&id=曲目ID&br=320`                   | 一次返回地址，后续同曲请求返回空地址和 `br=-1`，不能视为稳定可播           |
| Bilibili 搜索 | `types=search&source=bilibili&name=关键词&count=1&pages=1` | 本次样本返回空数组，不能据此认定整个平台不可用                             |

网易云搜索与播放地址请求携带本地预览的 Origin 时，观察到 `Access-Control-Allow-Origin: *`。这仅证明对应 API 响应允许无凭据跨域；当前项目的 CSP 仍会拦截渲染进程直接请求这个域名。

初次并行探测时，两次播放地址请求收到非 JSON 的 HTML 响应，后续请求成功。接入时必须处理 HTTP 错误、非 JSON 响应、空数组和空地址，不能把 HTTP 200 等同于可播放。

初始评估阶段仅验证接口和 HEAD 请求，未进行项目内实际试听。实施后的浏览器与桌面播放验证见文末；HEAD 本身不能证明解码和交互正常。

## 建议的数据模型

为 `Track` 增加可选引用，不扩展现有 `kind`，因此网络筛选、桌面初始化与持久化分支仍可复用：

```ts
interface GdMusicReference {
  provider: 'gd';
  platform: 'netease' | 'joox' | 'bilibili';
  trackId: string;
  pictureId?: string;
  lyricId?: string;
}
```

`Track` 新增 `remote?: GdMusicReference`，其中 `trackId` 始终用字符串；JOOX ID 包含加号等字符，使用 `URLSearchParams` 编码，不能手工拼接。

- 应用内 ID 建议为 `gd:netease:2652820720`，用于去重、队列、收藏和歌单。
- `source` 保存同样的稳定资源引用；播放器先识别 `remote` 并解析，不能把此引用直接赋给 Audio。
- 真实音频地址仅在播放会话中持有，不写回持久化的 `track.source`；地址可能带签名或时效参数。
- 现有手动添加的网络直链没有 `remote`，继续使用原来的播放路径。
- 搜索响应的 `source` 表示上游平台，项目的 `Track.source` 表示资源位置，两者不能直接照搬。
- API 的 `url_id` 已标为废弃，解析使用搜索结果的 `id`。
- 搜索结果没有时长时用 `duration: 0`，播放后沿用现有媒体时长回填。
- `br` 是实际返回音质，不能仅凭用户请求无损就显示 FLAC；格式需结合实际媒体信息。

## 请求层与播放流程

桌面版建议新增 `src/desktop/gd-music.ts`，通过已有 preload 桥接暴露有类型的方法：

```text
在线搜索页面
  → window.desktop.music.search({ platform, keyword, page })
  → 主进程固定域名请求、参数校验、限流、错误转换
  → 返回搜索结果

点击播放
  → 根据平台和曲目 ID 幂等加入音乐库
  → playTrack(track)
  → window.desktop.music.resolve(track.remote, quality)
  → 检查切歌序号后赋值 networkAudio.src
  → 复用收藏、歌单、播放队列、历史和系统媒体控制
```

IPC 沿用 `trusted(event)` 检查，只接收平台枚举、受限长度的关键字、资源 ID、页码与音质，不开放任意 URL 请求。请求固定指向公开 API，校验返回结构与 HTTP/HTTPS 媒体地址。

浏览器预览可共用不依赖 Electron 的参数和响应解析模块，并用 `fetch` 请求公开 API；`index.html` 的 `connect-src` 只增加该 API 的确切域名。不要关闭 Electron 的 `webSecurity`。音频继续走独立的网络 Audio，保留当前网络资源与本地均衡器的处理方式。

播放解析失败、切歌和重试需要明确处理：

1. 用户切歌或停止时取消不再需要的请求，并检查播放器已有的 `generation`，防止迟到的成功或失败覆盖当前状态。
2. 歌曲封面与歌词按需加载和缓存，其失败不阻止播放；用户手动编辑的歌词优先于自动歌词。
3. 长时间暂停后恢复或播放失败时，允许对同一曲目重新解析一次；不能因为 `loadedId` 相同一直复用旧地址。
4. 解析为空时明确提示“该歌曲暂不可用”，不会无限重试或悄悄换成同名的其他版本。
5. 搜索结果不整体写入音乐库；用户点击播放、收藏或加入歌单时，仅加入涉及的曲目。当前队列通过音乐库查找歌曲，因此入队前必须完成入库。

## 界面范围与请求预算

建议首版在「网络音乐」页增加「在线搜索」入口，默认网易云，JOOX 为可选平台。搜索使用明确提交和分页，支持播放、加入音乐库、收藏与加入歌单。保留顶部已有的库内搜索。

官方 API 说明当前列出的可用源为 `netease`、`joox`、`bilibili`，并标注每 5 分钟不超过 50 次请求。首版不应把文档参数中的全部平台都显示为可用，也不应默认同时查询多个平台。

- 20 条结果若每条立即加载封面和歌词，一次搜索就是 41 次 API 请求；再预取播放地址会超过文档限制。
- 列表先显示歌曲元信息与占位封面；当前播放歌曲再请求播放地址、封面和歌词。
- 主进程统一实现滚动窗口请求预算、同请求去重、短期缓存及有限并发；优先保障当前播放解析。
- 搜索缓存需要包含平台、关键字、页码和数量。不同平台分页行为需独立处理，不能只根据返回数量断言还有下一页。
- 超限或服务不可用时显示可重试状态。客户端限流只能约束本实例，无法保证同一公网出口下的总请求数。

## 使用条件

API 说明标注 CC BY-NC 4.0、非商业学习用途，要求注明「GD音乐台(music.gdstudio.xyz)」，同时声明限制下载和传播。公开接口可访问并不等于已取得音乐内容的分发或商用授权。

因此本方案以在线音乐源接入为范围。若计划商业发布或增加文件下载，需要先向提供方核实适用授权与使用条件；界面的音乐源说明应保留出处。

## 落地顺序与验收

1. 完成共享契约、GD 适配器、桌面 IPC 与浏览器预览请求，覆盖错误响应、空地址、编码和限流。
2. 接入稳定资源引用与按需解析，验证切歌竞争、暂停后失效刷新、同曲重试及原有直链回归。
3. 增加在线搜索与平台选择，接入加入库、收藏、歌单、按需歌词和出处说明。
4. 用可控响应验证搜索结果入库、去重和重启恢复；再进行真实 Electron 播放、进度拖动、连续切歌与失败场景验收。

首版建议优先打通网易云完整链路。JOOX 的真实解析有波动，Bilibili 本次未获得可用搜索样本，应保留为后续验证项。

## 实施状态

- `src/shared/gd-music.ts`：固定 API 地址、参数与响应校验、相同请求合并、搜索与资源缓存、50 次/5 分钟预算、两路并发与播放优先、请求取消及 15 秒超时。普通请求最多使用 45 个额度，剩余容量留给播放解析。
- `src/desktop/gd-music.ts`、`src/main.ts`、`src/preload.ts`：限定音乐源 IPC、主窗口来源校验、参数验证与独立请求取消。
- `src/renderer/components/OnlineMusic.vue`：网络音乐页在线搜索、平台选择、分页、播放、加入库、收藏、歌单和出处说明。网易云为默认平台，JOOX/Bilibili 标记实验；JOOX 暂不开放下一页，避免将固定返回量误作分页能力。
- `src/renderer/stores/library.ts`：按平台和曲目 ID 幂等入库，复用现有持久化；真实音频地址仅供播放，不写回歌曲记录。
- `src/renderer/stores/player.ts`：播放前解析、切歌取消与序号保护、失败后一次强制刷新、暂停超过 5 分钟后重新解析并恢复进度；封面和歌词按需加载，原文和翻译分别保存。
- `tests/unit/gd-music.test.ts`：映射、编码、参数校验、错误响应、缓存、请求合并、取消、并发优先级与限流。
- `tests/e2e/gd-music.spec.ts`：通过可控音乐源和音频验证搜索、收藏/歌单、进度、重载恢复、切歌竞争、过期刷新、重试上限、平台与分页。
- `tests/desktop/smoke.mjs`：通过真实主进程和 preload，使用受控接口与音频验证在线搜索、播放、歌词、收藏、持久化引用、参数拒绝和取消。

自动化使用可控资源验证客户端行为。第三方真实曲目可用性仍需实际网络环境验证，不能由自动化成功推断所有歌曲均可播放。
